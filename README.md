# Quick Shot — How to Play

**Quick Shot** is an online multiplayer trivia race for **one host and up to 10 players**. Players answer trivia questions, roll a die after getting a question right, and race along a 51-space board. The first player to land **exactly on space 50 (GOAL)** wins!

## What you need

- One person to act as **host**, ideally on a computer or large display.
- Each player needs a phone, tablet, or computer with a web browser.
- Everyone opens the same game website. Players can join remotely; they do not need to share Wi-Fi.
- The host needs an Excel question set (see **Preparing questions** below).

## Setting up a game

1. The host selects **HOST** and creates a room, then shares the displayed room code.
2. Players select **PLAYER**, enter the code and their name, and choose an available token/color.
3. The host uploads a question spreadsheet and starts the game once everyone has joined.
4. All players begin on **START (space 0)**. The host advances the game using the on-screen controls.

## The trivia round

1. The host displays a question to everyone. The game initially keeps players' buzzers **LOCKED**.
2. After a random delay of approximately **1–5 seconds**, eligible players can buzz in. Some board abilities change this timing or who can buzz.
3. The first eligible player to buzz gets the chance to answer. The host judges the response **CORRECT** or **INCORRECT**.
4. If the answer is incorrect, the next player in the buzz queue can try. The host may start or pause the **10-second answer timer**.
5. When a player answers correctly, the host reveals the answer and advances to that player's roll. If no one answers correctly, the host reveals the answer and moves on to another question.

The host can open a **private Answer Monitor** to see the correct answer and hint without revealing them to the players.

## Rolling and moving

- A player who answers correctly gets to roll a **six-sided die**.
- The rolling animation is visible to **the host and the player rolling**, not to the other players.
- The die rolls first; then the token moves along the board. The host's board follows the moving token.
- Special movement bonuses or choices may change how far the player travels.
- To win, a player must land **exactly on GOAL, space 50**. A roll that would go beyond space 50 is an **overshoot**: the player stays where they are and does not activate that space again.
- After three consecutive overshoots, the game limits the overshooting die faces to help the player reach the goal; an overshoot is still possible.
- If multiple players reach GOAL on the same movement (for example, through a piggyback), the tied players enter a **highest-die roll-off**. A tied roll-off repeats until there is one winner.

## Board spaces and abilities

The board has **51 spaces, numbered 0–50**. Landing on a special space activates its effect, unless otherwise specified.

| Space | What it does |
| --- | --- |
| **START** | All players begin here at space 0. |
| **Blank Space** 🟨 | No special effect. |
| **Add 2** +2 | Adds 2 spaces to the player's **next roll**. |
| **Add 3** +3 | Adds 3 spaces to the player's **next roll**. |
| **Double** ×2 | Doubles the number on the player's **next roll**. |
| **Choose** 🎯 | On their next roll, the player chooses a number from **1 to 6** instead of rolling randomly. |
| **Hint** 💡 | Gives the player a single-use hint they can use while answering a question. A hint counts as used only when activated; hints do not stack. |
| **Swap** 🔄 | The player chooses another player and confirms the swap. Their board positions exchange; neither new position triggers another landing effect. |
| **Piggy Back** 🐷 | The player selects and confirms another player to ride on. When that player next moves, the rider moves the same number of spaces too, provided the move does not overshoot. The ride is then consumed. |
| **Head Start** ⏱️ | On the next affected question, the player gets the normal buzzer unlock while other players wait an additional **5 seconds**. |
| **Solo** ♟️ | On the next affected question, **only the Solo player** may buzz, and their buzzer unlocks immediately. |
| **Locked Out** 🔒 | The player cannot buzz on the next affected question. |
| **GOAL** 🏁 | Land exactly on space 50 to win. |

A special ability that applies to a future question or roll stays available until its applicable use. Board landing effects do not chain simply because a player is swapped onto a special space.

## Piggyback rides explained

When a player lands on a Piggy Back space, they choose another player and press **Confirm**. The chosen player is notified: **“You've got a Piggy on your back!”** The host sees who hopped onto whose back. When the chosen player next makes a successful move, the rider follows by that same distance if they can do so without overshooting GOAL. Piggyback movement is included in the rider's total spaces moved and in both players' ride statistics.

## Winning and the final leaderboard

When a player reaches GOAL, the game plays the **dice animation**, then the **token movement animation**, and only afterward the **victory fanfare and confetti**. After the fanfare, the **Final Leaderboard** appears on every screen. It can be closed and reopened using **View Final Leaderboard**.

The leaderboard sorts by **Final Position** (highest board space first). Players on the same space share a place; the next place is skipped as appropriate (for example, **1st, 2nd, 2nd, 4th**). Gold, silver, and bronze medals mark the top three places.

Its columns are represented by icons; hover over an icon, or tap it on a touch screen, to see the statistic's name:

| Statistic | Meaning |
| --- | --- |
| **Place** 🏆 | Final rank, with ties based on board position. |
| **Player** 👤 | Player name and chosen token. |
| **Questions** ❓ | Number of trivia questions answered correctly. |
| **Final Position** 🏁 | Board space occupied when the game ended. |
| **Spaces Moved** 🏃 | Total actual movement, including bonuses, chosen rolls, and successful piggyback rides; moving backward in a swap does not subtract from this total. |
| **Blank Spaces** 🟨 | Number of blank spaces landed on. |
| **Extra Movement** ➕ | Extra distance added by Add 2, Add 3, or Double rolls. |
| **Choose Spaces** 🎯 | Number of Choose spaces landed on. |
| **Chosen Movement** 🎯👣 | Sum of movement values chosen for Choose rolls. |
| **Hints** 💡 | Hints actually used, not merely collected. |
| **Swaps** 🔄 | Times the player participated in a swap, as initiator or target. |
| **Piggy Backs** 🐷 | Piggy Back spaces landed on. |
| **Piggy Back Distance** 🐷👣 | Total distance traveled as a piggyback rider. |
| **Rides Given** 🚕 | Times the player was selected to carry another player. |
| **Ride Distance** 🚕👣 | Total distance carried by riders following this player's movement. |
| **Head Starts** ⏱️ | Head Start spaces landed on. |
| **Solos** ♟️ | Solo spaces landed on. |
| **Lock Outs** 🔒 | Locked Out spaces landed on. |
| **Overshoots** ⏩ | Rolls that would have moved the player beyond GOAL. |

## Host controls and player screens

- The host sees the board, a player list ordered by **current position**, the question, and the buzz queue.
- Clicking a player in the host list focuses the board on that token.
- **Zoom Out** shows the full board; **Zoom In** returns to the normal view focused on the leader. Rolling and movement automatically restore the normal view and follow the active player.
- The host can hide the room/question-set details to make more room for gameplay.
- Players see their own board view, buzzer, and available abilities. Notices explain Locked Out, Solo, Head Start, and piggyback effects.
- The host's **NEXT** button advances between the appropriate question, reveal, and roll stages.

## Preparing questions

Create an **.xlsx or .xls** workbook. Use the first worksheet and these **five required headers in columns A–E**, plus an optional creator-only **Show** column in F:

| A | B | C | D | E |
| --- | --- | --- | --- | --- |
| **ID** | **Question** | **Answer** | **Hint** | **Images** | **Show** |

- **ID, Question, and Answer** are required for every question. IDs must be unique within the sheet.
- **Hint** is optional.
- **Show** (column F) is for the question-set creator only. It is ignored by the game and never displayed to players or the host.
- **Images** is optional: supply a public `http://` or `https://` image URL or an Excel hyperlink to an image.
- The host uploads the workbook before starting. Invalid sheets are rejected with an explanation.
- Questions are selected without repeating a question ID until the set's unused questions are exhausted. Question history is tracked by **uploaded filename** (without extension), so reusing a filename retains its question history.
- The number displayed during play counts **questions shown in the current game**, rather than showing the spreadsheet's ID.

## Playing again

After a completed game, the host can start another round or return to the home menu using the game's end-screen controls. A new game resets player positions and in-game statistics. The question-history system is separate from the per-game question counter.

## Running the game locally or online

For local play, install **Node.js 20+**, then run:

```bash
npm install
npm start
```

Open `http://localhost:3000` in a browser. For online play, put the contents of this folder at the root of a GitHub repository and deploy the included `render.yaml` on **Render** (New → Blueprint). Alternatively, create a Render Web Service with build command `npm install` and start command `npm start`. Everyone joins through the same deployed URL.

**Hosting note:** Game state and question history can be lost if the hosting server restarts without durable storage. For reliable persistence across Render restarts, use a supported persistent disk and set `DATA_DIR` to its mounted directory. Use a single server instance. Browser reconnection works best when players retain their browser's saved site data.
